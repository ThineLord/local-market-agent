# Local Market Agent 0.3.0

Release date: 2026-11-09 · [中文发布说明](https://github.com/ThineLord/local-market-agent/blob/v0.3.0/docs/releases/0.3.0.zh-CN.md)

This release completes the P1–P3 workflow improvements: paper execution now requires a reviewed, content-bound intent, and the full evidence-to-settlement flow can be demonstrated locally.

## Changes

- Atomic, idempotent ledger opening/closing; daily and sandbox dry-runs use disposable database copies.
- Shared fail-closed screening/execution preflight, preserved observation times, actual UTC session loss and observed-peak drawdown. Invalid observations cannot alter risk baselines; held markets need fresh quotes.
- Per-intent approval with reviewer label, rationale, expiry and rejection history. Execution checks inputs/configuration and current risk under the same write lock as the fill. Public-source runs cannot disable approval.
- Run and execution receipts check content hashes and complete opening relationships. Legitimate closing remains replayable; legacy unsealed runs report their limitations.
- JSON CLI outcomes distinguish completed, rejected, pending, halted and failed runs. Invalid datasets and mixed sandbox outcomes return appropriate nonzero codes.
- Evidence packets bind source files and timing to an authored brief and explicit review. Reviewed settlement writes closing fills and provenance receipts atomically.
- An isolated 15-step synthetic CLI demo and a read-only “Your next step” panel show version, data time, blockers and copyable commands.

## Upgrade and migration

Use Python 3.11+, check out `v0.3.0`, and reinstall with `python -m pip install -e ".[dev]"`. Keep an independent backup before opening an existing database with a new version. Normal repository initialization creates additive equity, intent, approval, execution and settlement tables; it does not rewrite existing records. The dashboard opens databases read-only. Backdated simulations need separate databases; the new demo refuses to overwrite its output directory.

`paper-log` now prepares/pends rather than immediately filling. Use `paper-status`, `paper-approve`, `paper-execute`, and `paper-replay`. Scripts must handle exit codes 0 completed/dry-run/approved, 1 failed, 2 invalid arguments/data, 3 rejected, 4 pending approval, 5 halted. Sandbox aggregation prioritizes failed, halted, rejected, then pending. The static legacy fixture is historical and may correctly be rejected today; use the fresh synthetic demo for a complete current-time flow.

```bash
python scripts/demo_workflow.py --output data/reports/workflow-demo
LMA_DB_PATH=data/reports/workflow-demo/demo.sqlite python ui/server.py --port 8503
```

## Validation and remaining limits

The final feature suite passed 433 offline tests, with one optional network test skipped; Ruff, release metadata, JavaScript syntax and whitespace checks passed. The real browser validated desktop/mobile layout and clipboard copying. The CLI demo completed pending → approval → fill → retry → replay → settlement → replay, with one opening and one closing fill.

A bounded public Kalshi/NWS sample passed provenance checks but remains blocked by missing liquidity and no reviewed brief. No estimate, public-market approval or profitable result was fabricated. NWS data is supporting research; the market's stated settlement source is The Weather Company.

This remains paper-only experimental software. Actor names are trusted local audit labels, not authentication. Hashes detect content changes but are not signatures; replay does not rerun an LLM/strategy. Equity peaks are observed, not continuous, and session start uses the previous UTC session's last valid observation. No live order capability, paid model call, profitability or production-readiness claim is added.
