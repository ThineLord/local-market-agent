## 独立审查解决的问题

1. 被拒绝的行情仍可能改变权益峰值：改为先校验，再记录可信权益，并检查请求的市场 ID。
2. 哈希之外的持仓关联不完整：统一核对意图、行情、简报、信号、风险、审批、订单、成交和持仓的身份/市场/方向/参数。
3. 旧研究材料可能被误用为最终结算来源：要求最终来源 URL 对应结算规则，且采集/已知发布时间不早于结果、采集不晚于结算快照。

4. 发布审查发现演示报告仍写默认导出目录：新增 `report-daily --export-dir`，演示传入自己的输出目录，并验证既有默认导出保持不变。另更正通用审批链与证据包专属来源审核的区别。

以上发现均由 Codex 修复，并经独立复审及最终提交的 CI 后合并。subagent 技术审查不冒称 GitHub APPROVED 审查。

## 真实公开样本

选择 Kalshi `KXHIGHNY-26NOV09-T57`，采集时间为 2026-11-08 17:57:18 UTC。采集范围限定于公开只读市场/系列响应和 NWS 的预报、KNYC 观测，无凭证或交易 API。

- 四份来源凭据、两条证据；来源文件 SHA-256、来源生成/观测时间、采集时间和快照时点对应检查通过。NWS 的 `published_at` 规范化字段分别取预报 `generatedAt` 与观测 `timestamp`，不据此声称已验证首次公开发布时间；采集时间单独验证。
- 实际 `liquidity_dollars` 缺失，且没有经过审核的概率简报，流程正确显示阻断；没有生成公开市场订单或伪造人工审批。时间流逝后，快照也会因过期被拒绝。
- 两条天气证据来自同一发布机构，不能当作两个独立信息源。
- 该市场规则指定 **The Weather Company** 为最终结算来源。NWS 预报和观测只作研究支持，不能替代最终结算凭据；市场尚未结算，不声称已完成真实市场结算验证。

来源：[Kalshi 公开市场数据说明](https://docs.kalshi.com/getting_started/quick_start_market_data)、[该市场公开响应](https://external-api.kalshi.com/trade-api/v2/markets/KXHIGHNY-26NOV09-T57)、[NWS 预报](https://api.weather.gov/gridpoints/OKX/33,37/forecast)、[KNYC 观测](https://api.weather.gov/stations/KNYC/observations/latest)。原始响应、验证 JSON 和演示数据库只保存在本地忽略目录；仓库不发布这些原始数据。

## 使用边界

已实现并验证功能流程；真实样本仍需具备完整报价、独立证据判断和明确审核，才能继续形成有效研究意图。没有盈利、连续市场监测或生产可用性结论。审核人名称是可信本地标签，内容哈希不是数字签名，回放不是重新运行模型。权益峰值是已观察值；UTC 日初权益采用上个交易日最后有效观察值。实盘能力和默认安全开关保持不变。
