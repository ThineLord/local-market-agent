# 0.3.1 真实公开数据流程验收

日期：2026-11-09（香港时间）。范围：公开只读数据、隔离模拟账本；Codex 实现，subagents 独立审查与合并。未调用 bots、实盘/私有交易接口、付费模型，未修改用户既有数据库。

## 复现与根因

| 问题 | 根因 | 修复 / 保留的真实限制 |
| --- | --- | --- |
| Kalshi 流动性未知 | 仅读取当前响应已缺失的旧字段 | 读取顶档数量并规范为保守美元容量；实际不足仍拒绝 |
| 旧流动性单位 | cents 和 dollars 被当作同单位 | 明确转换及优先级，缺失不能用成交量补齐 |
| 没有简报却“已审核” | research-review 不要求 brief 存在 | 无简报不能生成研究审核；先成稿再核对确切内容 |
| 无概率观察简报显示 ready | ready 只检查硬条件，不看审核/策略 | 分开显示完整性、审核、策略、组合风险、订单审批 |
| 准备拒绝含糊且写入状态 | 泛化风险异常；先写权益再否决 | 保留具体策略/风险理由；准备使用只读权益投影 |

本版未增加 MarketSnapshot/数据库字段；既有封存对象结构不变。未降低 $100 深度门槛、置信度、证据质量、时效或审批要求。公开 API 的当前字段/订单簿语义参见 [Kalshi market](https://docs.kalshi.com/api-reference/market/get-market)、[orderbook](https://docs.kalshi.com/api-reference/market/get-market-orderbook)；旧 cents 字段弃用参见 [官方 changelog](https://docs.kalshi.com/changelog)。

## 最终真实采集与审核

市场：`KXHIGHNY-26NOV09-T57`。本地验收目录：`data/reports/v0.3.1-validation/public-run-final/`。原始响应、数据库和截图仅留本地忽略目录，不上传仓库。

- 真实市场与订单簿顶档一致：YES bid 0.12 / 30 合约；YES ask 0.13 / 10 合约。YES 可买 $1.30，NO 可买 $26.40；保守值为 $1.30。这是顶档美元容量，不是整簿深度。
- 对同一真实响应运行 v0.3.0 适配器得到 liquidity=null，新版得到 1.3；版本对照保存在 `liquidity-comparison.json`。
- 最终六市场保守容量：T57=$1.30、B61.5=$0.20、B63.5=$9.58、B59.5=$2.34、B57.5=$12.571、T64=$0.00。动态值只对应当次采集，不保证现在仍相同。
- 两条天气证据同属 NWS，不能当独立发布机构。预报生成时间与观测时点明确标注，不声称核实首次公开时间；采集时点另行保留。
- 自动草稿为 observation-only，概率 null、置信度/证据交易质量 0，保留经济性 veto，不伪造“可交易”建议。原始数值被写入摘要并由 subagent 对照来源检查。

- 最终结算来源为 The Weather Company。NWS 只是研究支持，不能替代最终结算结果。

第一次采集也被保留；检查发现草稿静态 veto 中的“需审核”文字在审核后仍可能引起误解，已改为“仅观察、不形成交易建议；来源审核本身不能授权交易”，随后全新采集并独立复核最终包。

## 实际命令与账本结果

七步 CLI 验收：来源包检查 → 成稿包检查 → 附审核检查 → 准备 → 重试准备 → paper-status → workflow-status。另有独立 `packet-review` 命令生成确切审核凭据。

附审核检查返回 `research_review=valid`，不再出现缺简报或缺审核阻断。真实剩余阻断：$1.30 深度不足、没有可辩护的校准概率/交易建议。两次 `packet-prepare` 均退出 3；行情年龄检查在实际提交时通过，拒绝不是过期导致。

全部 17 张业务表前后哈希相同：`fd1bc669a2ac6f956dc9437c14612b3b3cd4fd4b64d17cda02b6aafb2e6f4d4d`。所有业务记录为零，包括意图、审批、订单、成交、权益基线。用户已有账本不受影响。因没有合法意图和持仓，公开样本的执行、成交回放、结算不适用；没有为“跑全流程”编造这些环节。
