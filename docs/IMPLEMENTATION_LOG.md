### Adapter and paper clues

Reproduced on the same pin before editing:

- Empty Polymarket identity became the string `None`. `polymarket.py` used `str(id or conditionId or slug)`. `{}`, all-null ids, and a blank id with a null slug each produced market id `None` and URL `https://polymarket.com/event/None`. A missing id now raises `Polymarket market response is missing its id` (`_market_id`). Numeric id `12345` stays `12345`, condition id `0xabc` is used when id is absent, and the literal slug `literal-None` is preserved. A null slug falls back to that id instead of the string `None`.
- `active="false"` became open. `bool("false")` is true, so a payload with only that string was status `open`. `active="true"` and `closed="false"` became `closed`. Real booleans `True`/`False` were already correct and stay open. `_payload_flag` accepts only the strings `true` and `false`, case-insensitively, and otherwise keeps `bool()`.
- Two labels were split into three when one contained a comma. `'["Alpha, Beta", "Gamma"]'` became `["Alpha", "Beta", "Gamma"]`. `'["Yes, please", "No"]'` did the same. Two labels that each contain a comma, `'["A, B", "C, D"]'`, became four strings, not three; the defect is the comma split, and the three-way case is the one with a comma in one of two labels. Quoted JSON lists now use `json.loads`. `["Alpha, Beta", "Gamma"]` and the two `S&P 500` labels stay intact. Unquoted `Yes,No`, a real list `["Yes", "No"]`, and JSON `[true, false]` still become `["Yes", "No"]` and `["true", "false"]`.
- Kalshi JSON boolean `true` on legacy `yes_bid` became `0.01`, because `float(True) / 100` is `0.01`. `yes_bid: False` became `0.0`. `yes_bid_dollars: True` became `1.0`. The strings `"true"` and `"false"` already raised `ValueError` and were not turned into `0.01`.
